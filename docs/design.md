# 位置情報RPG（仮）設計メモ

> 相棒と一緒に、歩いて街を育てる。何も失わない。
> その上に、生成されたシナリオが乗る一話完結RPG。

最終更新: 2026-07-25

---

## 1. コンセプト

現実の街を舞台にした、**戦闘のない**位置情報RPG。

歩いた場所が育ち、そこに生き物が戻ってくる。パートナーAIが同行し、
LLMが生成したシナリオを一緒にクリアしていく。

**想定プレイヤーは在宅中心・行動範囲が狭い人**（＝作者自身）。
既存の位置ゲーが「たくさん動く人が強い」のに対し、本作は
**同じ場所に通い続ける人が強い**設計にする。ここが最大の差別化。

### 二層構造

| 層 | 内容 | 性質 |
|---|---|---|
| **土台** | 街を育てる（成長・図鑑・振り返り） | 永続。飽きても残る |
| **上物** | 一話完結シナリオRPG | 消費コンテンツ。無限生成 |

上物に飽きても土台は残る。土台だけでも成立する。

---

## 2. 設計原則（最重要）

この企画は**負のフレームを一切使わない**ことを最優先とする。
理由：自作ゲームを自分でプレイする場合、自分を縛る仕掛けは効かない。
仕掛けが見えているため、ストレスにしかならない。

### やらないことリスト

- ❌ **減衰・消滅**（陣地が減る、塗りが消える）
- ❌ **維持ノルマ**（サボると損をする）
- ❌ **催促通知**（「3日行ってません」「陣地が減っています」）
- ❌ **パートナーが寂しがる/責める**（たまごっち系の罪悪感）
- ❌ **他プレイヤーとの直接比較・ランキング**
- ❌ **失敗・ゲームオーバー・期限切れによる損失**
- ❌ **戦闘システム**（スコープ的に作らない）

### やること

- ✅ **歩いたら必ず前進**。ゼロリスク
- ✅ **久しぶりに開いても、ブランクに一切言及しない**
- ✅ 期限は「期待」を作るために使う（季節限定＝逃しても何も減らない、来年また来る）
- ✅ 内発的動機の3要素をすべて供給する
  - **自律性** … 断れる、指示されない
  - **有能感** … 街が育つのが見える
  - **関係性** … パートナー

## 3. コアループ

```
出発前  パートナーが軽く誘う（断れる）／シナリオを受ける
  ↓
歩行中  通った道が育つ。パートナーが2〜3回だけ反応する
  ↓
帰宅後  振り返り。パートナーが語る。図鑑が増える
```

## 4. 土台システム

### 4.1 塗り（成長）

- **減衰なし**。上書きでアップグレードのみ
- 状態 = 歩行ログの累積。冪等で、いつでも再計算できる
  - → 時刻依存の計算・バックグラウンドジョブ・オフライン同期が全部不要。**実装が劇的に軽くなる**
- グリッドは H3 等のヘックスセル。行動範囲が狭い前提なので**解像度は高め**に取る

### 4.2 成長段階：無限だが線形ではない

> **無限にするのは「組み合わせ」であって「段階」ではない**

Lv.847の草を作らないための原則。

- 道単体：草 → 花 → 低木 → 木 → 生き物が住みつく
- **その先は分岐する**。歩き方で分岐先が変わる
  - 朝ばかり歩いた道 → 朝の性質
  - 雨の日に歩いた道 → 水の性質
  - 夜ばかり → 夜の性質
- 有限のパーツ × 分岐 = 組み合わせ爆発で無限に見せる

### 4.3 単位の繰り上がり

個別の道がカンストしても、**面としての完成度**が残る。

```
道 → 小径（3本繋がる） → 一帯（区画が揃う） → 地域
```

「あと1本でこの区画が繋がる」が、そのまま今日歩く理由になる。
無限に伸びるが、途中に**局所的な完成（マイルストーン）**を置いて達成感を作る。

### 4.4 図鑑

浄化ではなく**育成の成果**として生き物・植物が現れる。

- 中身は OSM の地物から自動で紐づく
  - 川沿い → カワセミ、トンボ / 坂の上 → 眺望 / 神社の木 → フクロウ / 公園 → 季節の花
- **有限**：基本図鑑（数ヶ月で埋まる。達成感の役）
- **無限**：季節4 × 時間帯3 × 天候3 = 36通りの変奏。同じ生き物でも「冬の朝」は別枠
- **同じ場所に通うほど出やすい**（例：カワセミは同じ川に10回通って初めて現れる）
  → 行動範囲の狭さが有利になる中核メカニクス

### 4.5 振り返り（長期継続の本体）

- **月次スナップショット**：その月の地図を1枚の画像として永久保存
  - 何ヶ月も続けると、引っ越し・転職・旅行が地図のアルバムとして見える
- パートナーが語る形式にする（Wrapped 的な体験）
- 生成テキストの出口はすべてここに集約する（＝歩行中に待たせない）

## 5. パートナーAI

役割は「機能追加」ではなく**動機設計の柱**（関係性の供給）。

### モデル：犬の散歩

責めない。ただ喜ぶ。それで飼い主は毎日歩く。
**罪悪感ゼロで最強の継続率**を出している現実の仕組みをそのまま実装する。

### 4つの仕事

1. **出発前に軽く誘う** — 「あっちの方、行ってみたいな」。指示ではなく願望。断ってもOK、催促しない
2. **歩行中に喜ぶ** — 発見・変化に反応。**1回の散歩で2〜3回だけ**（沈黙のデザインが命）
3. **帰宅後に語る** — 振り返りのナレーター。LLMの主戦場
4. **「今日どこ歩く？」に答える** — 天気・時間・履歴を踏まえた提案。**ゲーム抜きで実用的**なので、ゲームに飽きてもアプリが残る

### 記憶を持つ

> 「ここ、初めて来た日は何もなかったね」

事実は歩行ログのDBから渡し、LLMは文章化のみ担当。
→ ハルシネーションが構造的に起きない。

### スコープ防衛

- **姿を持たせない**（光の粒などの抽象表現）、または
- **その土地に戻ってきた生き物がそのままパートナー**になる（図鑑アセットを流用、追加コストほぼゼロ）
- 性格は歩いた場所で決まる（水辺ばかり歩く人には水辺寄りの相棒）

## 6. シナリオRPG（上物）

### 戦闘を作らない

| RPG要素 | 本作での実装 |
|---|---|
| 敵 | 到達すべき場所 + 必要な歩数。**強い敵 = 遠い / 長い** |
| 戦闘 | なし。そこまで歩けば解決 |
| レベリング | 街の育成をそのまま流用 |
| 謎解き | 場所を特定する行為。ナビゲーション自体がパズル |

追加実装は **シナリオ生成・配置・進行管理のみ**。戦闘UI、アニメ、アセット不要。
「強い敵 = 長い距離」なので、数値インフレがそのまま運動量になる（Lv.847問題が起きない）。

### 3層構造

| 層 | 単位 | 期間 | 備考 |
|---|---|---|---|
| セッション | 散歩1回 | 30分 | |
| **一話** | 散歩1〜3回 | 数日 | 一話完結。逐次消化できる |
| **シナリオ群（章／アーク）** | 5話前後 | 2〜4週間 | ここで完結。バッドエンドもあり |

5話 ≒ 散歩10〜15回 ≒ 2〜4週間。
**「生活圏を一巡する期間」とほぼ一致する**（§9の規模感を参照）。
街を一周する頃に物語も完結する。

- **期限なし・失敗なし・中断自由**。3ヶ月放置しても続きから
- **敵は攻めてこない**。シナリオを受けていなければ何も起きない

### 長期一貫性：骨格を先に一括生成する（最重要）

5話にまたがる伏線と整合性を、話ごとの逐次生成で保つのは不可能。
3話目で1話目の設定を忘れる。

**アーク開始時に、まとめて生成してDBに固定する：**

- 全5話の粗筋
- 登場人物・舞台となる場所（OSMから事前選定済みの候補を渡す）
- **結末候補を3つ**（グッド／ビター／バッド）

各話の詳細は、このプロットに沿って後から肉付けするだけ。
結末を先に決めておけば分岐も破綻しない。**逐次生成をやめるのが肝。**

### 中断対策：パートナーが「前回までのあらすじ」を語る

アークが長いぶん途中で放置される（放置に罰はない、は維持）。
問題は「戻ってきた時に話を忘れている」こと。
→ パートナーの役割として自然、かつLLMの得意分野。

### 街の状態が次のアークの生成材料になる

アークが終わっても街は残る。**次のアークを生成するとき、今の街の状態をプロンプトに入れる。**

- 「この一帯はもう森になっている」
- 「川沿いにカワセミが戻っている」

→ **自分が育てた街の現状が、次の物語の舞台設定になる。**
歩くほど次の物語の材料が増える。第1章と第5章では同じ場所が違う顔で登場する。
土台（街育成）と上物（シナリオ）が本当に接続する部分。

### 謎解きは「型」を固定する

答えを検証できない謎は事故る。**型は有限で手書き、パラメータとフレーバーだけLLM。**

型の例（10個もあれば無限に見える）：

- 「◯◯が見える場所を探す」
- 「3つの△△を順に訪れる」
- 「朝にここ、夜にあそこ」
- 「一度も通ったことのない道を経由して◯◯へ」

### ジャンル指定（プレイヤーが選ぶ）

プレイ前にジャンルを指定 → その通りにシナリオが生成される。

- 実装コストはほぼゼロ（プロンプトに1語足すだけ）なのに体験が根本から変わる
- 「自分の物語を選ぶ」＝内発的動機の**自律性**を直接供給する
- 例：ほのぼの / ミステリー / ホラー / 冒険 / 日常

同じ画面で**緊張感（難易度）も選べる**ようにする。

| モード | 内容 |
|---|---|
| のんびり | 失敗なし。分岐だけ |
| ふつう | 分岐＋章の完結 |
| ハード | 期限あり、バッドエンドあり |

> **押し付けられた期限は義務。自分で選んだ期限は挑戦。**

同じルールでも選択権があるだけで負のフレームが消える。実装はフラグ1つ。
生活リズムに合わせて月ごとに変えられるのも大きい。

### 連続性と分岐

一話完結だが、**前回の結果が次回に影響する**。
「続きが気になる」＝損失ではなく期待による動機なので、原則に反しない。

**分岐の入力は「成否」ではなく「選択」。**

- 二又に来たらどちらを選ぶか。**どちらも正解**。物語の進む方向が変わるだけ
- 軸は「良い/悪い」ではなく **「明るい/暗い」**
  - ホラーを選んだ人にとって暗い展開は**報酬**。良し悪しではなく色

→ 歩けば必ず前進するのに、毎回違う物語になる。連続性と一回性が罰なしで両立する。

### エンディング＝コレクション

**「ゲームオーバー」ではなく「そのシナリオ群（章）の完結」。バッドエンドもエンドなので達成。**

一話単位のバッドエンドは軽いが、**数週間追いかけた物語の結末なら重みがある**。
名作の多くはビターエンドであり、コレクションとしての価値も高い。

- エンディングを図鑑と同じ棚に並べる（全何種／既収集何種）
- バッドエンドを**わざと見に行く**動機が生まれる
- 「悪い結末」が損失ではなく**入手**になる

これにより、失敗判定を残しても罰にならない（別ルートに入っただけ）。

**リセットされるのはシナリオの進行状態のみ。
街の成長・図鑑・スナップショットは絶対に消さない。**

#### 文言ルール

| ❌ | ✅ |
|---|---|
| GAME OVER | 第3話 完 |
| 失敗しました | エンディング B に到達 |
| もう一度挑戦 | 次の話へ |
| 敵に負けた | 物語が別の方へ進んだ |

### 絶対のルール：時間経過では悪化させない

世界を動かすのは**プレイヤーの行動だけ**。

歩かなかった日は、物語の中でも何も起きていない。
3ヶ月ぶりに開いても、話は止まったまま待っている。
**「久々に開いたら大惨事」を一度でも起こしたら終わり。**

（＝「今日歩かないと悪いシナリオになる」は減衰の再発明。名前が違うだけで構造は同じ）

### 安全設計（必須）

**LLMに場所を選ばせない。** システム側が OSM タグで候補を絞り、
その中からLLMに割り当てさせる。

- 配置可能：公園、河川敷、神社、駅、公道、公共施設
- 配置禁止：民家、学校、病院、私有地、線路、危険箇所
- 自宅周辺のぼかし機能を最初から入れる

## 7. LLM運用方針

### 任せる

- 場所ごとのフレーバー（パートナーの一言として出す＝世界観を作り込まずに雰囲気が出る）
- 図鑑の記述文
- シナリオのフレーバーとパラメータ
- 月次振り返りの文章

### 任せない（手で決める骨）

- ルール・経済・成長の分岐ロジック
- 図鑑のカテゴリ体系
- 謎解きの型
- シナリオ配置場所の候補選定
- **実在の場所の事実**（歴史・由来は書かせない。書けるのは情景と感覚のみ）
  - ✅「登り切ると空が広い」 / ❌「この神社は江戸時代創建」

### コスト構造

**場所は全ユーザーの共有資源。** 同じ坂のテキストは1回生成してDBに入れれば全員が使う。
→ **コストはユーザー数ではなく地点数にしか比例しない。**

- 1地点あたり約300トークン、Haiku級で十分
- 10万地点でも数十ドル規模
- **MVP（自分の家の周り数百地点）なら実質タダ**

### レイテンシ

全て**非同期 + 事前生成 + キャッシュ**。エリアに初めて入った時点でバックグラウンド生成。
表示は歩き終わったあとの振り返り画面 → 設計と自然に噛み合う。

## 8. 世界観

**凝らない。** テキスト量とアート量でスコープが爆発し、確実に完成しなくなる。

必要なのは A4 半ページ：

- キーワード3語：**育てる / 戻ってくる / 一緒に歩く**
- トーン指定（静かで、説明しすぎない、2〜3文）
- 図鑑カテゴリ体系（水辺 / 高所 / 樹木 / 市街 / 夜 …）
- 出力JSONスキーマ

肉付けは全部LLMに回す。

---

## 9. 技術メモ

- **グリッド**：H3 / S2 のヘックスセル。面積計算・判定・サーバ負荷すべて有利
- **GPS精度**：5〜15m、ビル街ではさらに荒れる。セル単位で吸収する
- **移動手段判定**：電車・車の除外（速度＋加速度センサー）は必須。ないとチートで崩壊
- **バッテリー**：常時バックグラウンド測位はOS制限とバッテリーの両面でつらい。
  「アプリ起動中だけ育つ」セッション型に割り切る選択肢も有力
- **地図データ**：OSM / 国土地理院。地物タグ（神社・階段・坂・橋・公園・踏切）が図鑑とシナリオの素材になる
- **状態管理**：減衰がないので `状態 = 歩行ログの累積`。再計算可能・オフライン耐性あり

### 規模感（自宅から500m圏 ≒ 0.78km²）

- 10m グリッドで約7,800セル、うち道があるのは1〜2割 = **800〜1,500セル**
- 1日2km歩くと約200セル/日 → **単純な塗り尽くしなら4〜7日で終わる**
- → だから「塗り尽くし」をゴールにしない設計（分岐・繋がり・季節変奏・シナリオ）が必須

---

## 10. MVP スコープ

**まず自分の家の周り500m圏だけで成立させる。**

1. 歩行ログ取得 → セル塗り → 段階アップ（減衰なし）
2. 図鑑（基本カテゴリのみ、季節変奏なし）
3. パートナー：帰宅後の一言のみ（出発前の誘いは後回し）
4. 月次スナップショット
5. LLM生成は事前バッチで数百地点だけ

**後回しでいいもの**：シナリオRPG、謎解き、分岐成長、季節変奏、他プレイヤー要素

## 11. 決定事項ログ

| 論点 | 決定 | 理由 |
|---|---|---|
| 減衰 | **なし** | 負のフレームを排除。実装も軽くなる |
| 囲む or 塗る | **塗る** | 探索の楽しさを優先 |
| シーズンリセット | **なし** | ソロ完結なら積み上がる感覚が優先 |
| 上限 | **なし（分岐で無限）** | ただし線形インフレは禁止 |
| CPU対戦相手 | **なし** | 現実の街をAIに侵食されるのは不快。代わりにパートナー |
| パートナー | **あり** | 動機設計の柱（関係性）。LLMの受け皿 |
| 戦闘 | **なし** | スコープ防衛。歩くことが行動 |
| 世界観 | **最小限** | 骨だけ手書き、肉付けはLLM |
| シナリオのジャンル | **プレイヤーが指定** | 自律性の供給。実装コストほぼゼロ |
| 難易度・緊張感 | **プレイヤーが選ぶ** | 自分で選んだ制約は罰にならない |
| シナリオの連続性 | **あり**（前回の結果が次回に影響） | 期待による動機。散歩に出る理由になる |
| 分岐の入力 | **選択**（成否ではない） | 「歩けなかった」を入力にしない |
| シナリオの粒度 | **3層**（散歩／一話／章5話前後） | 章の完結が振り返りの単位になる |
| シナリオ生成方式 | **章の骨格を先に一括生成して固定** | 逐次生成では長期一貫性が保てない |
| ゲームオーバー | **なし＝「章の完結」** | バッドエンドもエンド。表現の問題 |
| バッドエンド | **あり。コレクション化** | 損失ではなく入手にする |
| 時間経過での悪化 | **絶対になし** | 減衰の再発明を防ぐ |

## 12. 保留・要検討

- 1日の標準歩行距離をどこに置くか（→ 成長速度の基準になる）
- バックグラウンド測位 vs セッション型のどちらを取るか
  - 前者：「ながら」で育つが、実装とバッテリーがつらい
  - 後者：「散歩に出るぞ」という儀式になる。在宅中心の生活には合いそう
- エンディングの総数と分岐の深さ（LLM生成でどこまで担保するか）
- ジャンルの選択肢をいくつ用意するか
- 他プレイヤーの存在をどこまで見せるか（現状は完全ソロ想定）
- マネタイズするのか、自分用に留めるのか
- パートナーの姿（抽象表現 or 生き物流用）

## 13. リスク

| リスク | 対策 |
|---|---|
| スコープ爆発 | 戦闘・アート・長編ストーリーを作らない。MVPを500m圏に限定 |
| 現実の場所への物語配置 | LLMに場所を選ばせない。OSMタグで公共空間のみに限定 |
| 位置情報の露出 | 自宅周辺ぼかしを初期実装 |
| 歩きスマホ・私有地侵入 | 歩行中はUIを最小化。危険箇所を配置候補から除外 |
| LLMの事実誤り | 事実はDBから渡す。情景と感覚のみ生成させる |
| コンテンツ枯渇 | 分岐 × 季節 × 時間帯 × 天候 の組み合わせ、およびシナリオ無限生成 |
