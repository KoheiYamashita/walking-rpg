# 位置情報RPG（仮）設計メモ

> 相棒と一緒に、歩いて街を育てる。何も失わない。
> その上に、生成されたシナリオが乗る一話完結RPG。

最終更新: 2026-07-30

---

## 1. コンセプト

現実の街を舞台にした、**戦闘のない**位置情報RPG。

歩いた場所が育ち、そこに生き物が戻ってくる。パートナーAIが同行し、
LLMが生成したシナリオを一緒にクリアしていく。

**想定プレイヤーは在宅中心・行動範囲が狭い人**（＝作者自身）。
既存の位置ゲーが「たくさん動く人が強い」のに対し、本作は
**同じ場所に通い続ける人が強い**設計にする。ここが最大の差別化。

### 二層構造

| 層 | 内容 | 性質 |
|---|---|---|
| **土台** | 街を育てる（成長・図鑑・振り返り） | 永続。飽きても残る |
| **上物** | 一話完結シナリオRPG | 消費コンテンツ。無限生成 |

上物に飽きても土台は残る。土台だけでも成立する。

---

## 2. 設計原則（最重要）

この企画は**負のフレームを一切使わない**ことを最優先とする。
理由：自作ゲームを自分でプレイする場合、自分を縛る仕掛けは効かない。
仕掛けが見えているため、ストレスにしかならない。

### 自己透明性の原則（正のフレームにも適用される）

「仕掛けが見えているため効かない」は**賞賛にも当てはまる**。
パートナーの喜びも、自分が書いたプロンプトの出力だと知っている。
自己透明性に耐えて残るのは3つだけ：

1. **本物の記録** — 実際に歩いたログ、スナップショット、「初めて来た日」の事実
2. **本物の予測不能性** — LLM生成シナリオの中身は自分でも読むまで分からない
3. **現実の報酬** — 散歩自体の気持ちよさ、実際の街の発見

この設計の耐久コアは**振り返り・スナップショット（§4.5）**。
パートナーは「動機の柱」ではなく**本物の記録の語り手**として設計する（§5）。

### やらないことリスト

- ❌ **減衰・消滅**（陣地が減る、塗りが消える）
- ❌ **維持ノルマ**（サボると損をする）
- ❌ **催促通知**（「3日行ってません」「陣地が減っています」）
- ❌ **パートナーが寂しがる/責める**（たまごっち系の罪悪感）
- ❌ **他プレイヤーとの直接比較・ランキング**
- ❌ **失敗・ゲームオーバー・期限切れによる損失**
- ❌ **戦闘システム**（スコープ的に作らない）

### やること

- ✅ **歩いたら必ず前進**。ゼロリスク
- ✅ **久しぶりに開いても、ブランクに一切言及しない**
- ✅ 期限は「期待」を作るために使う（季節限定＝逃しても何も減らない、来年また来る）
- ✅ 内発的動機の3要素をすべて供給する
  - **自律性** … 断れる、指示されない
  - **有能感** … 街が育つのが見える
  - **関係性** … パートナー

## 3. コアループ

```
出発前  パートナーが軽く誘う（断れる）／シナリオを受ける
  ↓
歩行中  通った道が育つ。パートナーが2〜3回だけ反応する
  ↓
帰宅後  振り返り。パートナーが語る。図鑑が増える
```

### セッションの区切り

- **標準セッション：30分 ≒ 2km**（一般的な散歩1回分）。
  成長速度・謎チェーンの段数・話の長さは、すべてこれを1単位として調整する
- **開始は手動**。「散歩に出るぞ」のボタンが儀式になる（セッション型の利点をそのまま使う）
- **終了は自動**。自宅付近＋移動停止を検知して「おかえり」を出す（終了の押し忘れを構造的に消す）
- **開始を押し忘れた日**：歩数計APIから距離だけ拾い、パートナーが言及する
  （「今日はけっこう歩いたんだね」）。位置がないので街は育たないが、**なかったことにもならない**
  - 押し忘れ＝「歩いたのに損した」は実質的な損失であり、§2と正面衝突する。その救済

### 歩行中のフィードバック

**画面はONのまま携行するのが基本**（ポケットに入れてもよいが、前提にしない）。
ただし**見続けることは要求しない**。画面に出続けるのは最小限（地図＋記録中の表示だけ）：

- **振動1回＝「何かが起きた」の印**。それ以上の情報は出さない
- 音声・通知文・リアルタイム演出はなし
- 信号待ちなどで見た場合も、出るのは1〜2文の断片だけ（§6の謎テキストと同じルール）
- 中身は帰宅後の振り返りで開く。**「何が起きたんだろう」を持ち帰らせる**のが狙い
- 画面ONでも**歩行中に操作を要求しない**（歩きスマホ対策はUI最小化で維持）

**インタラクションのリズム：移動中は無音、到達点だけが操作の点。**

- 場所に着く → 振動 → **立ち止まって受け取る**（断片1〜2文を読む＋最大1タップ）
- 歩きながら読ませない。その場で考え込ませない（数秒で歩行再開できる分量）
- 断片の統合・考察・次のヒント解錠などの重い作業は帰宅後（§6と同ルール）

### ウォークスルー：ある火曜日の30分

沈黙のデザインの実際。これが基準の体験になる。

> **16:40 出発前（30秒）**
> アプリを開く。パートナーの一言「川の方、しばらく行ってないね」（誘い。断ってもいい）。
> 謎が進行中なら候補地が地図に点灯している。「出発」を押す。画面はONのまま手に持つ。
>
> **16:42〜17:05 歩行中（見続けない）**
> 川べりで振動が1回。画面には地図と記録中の表示だけ。信号待ちにちらっと見ると「何かを見つけた」とだけ。
> 謎の候補地の公園に着くとまた振動。「ここではなかったみたい。でも、ベンチの下に古い切符」。
> 外れでも歩数は増え、道は育っている。
>
> **17:08 帰宅（自動検知）**
> 「おかえり」通知。振り返りを開く：今日の道2.3km、いつもの道が1段階育った（低木→木）。
> さっきの振動の中身は川辺の青い羽根（カワセミの予兆。図鑑にはまだ載らない）。
> 切符の断片が手帳に入り、謎の候補が2つに絞られた。
> パートナーが今日のログと1ヶ月前の記憶から一言。
> **翌日の楽しみが2つ残った状態**でアプリを閉じる。所要1分。

## 4. 土台システム

### 4.1 塗り（成長）

- **減衰なし**。上書きでアップグレードのみ
- 状態 = 歩行ログの累積。冪等で、いつでも再計算できる
  - → 時刻依存の計算・バックグラウンドジョブ・オフライン同期が全部不要。**実装が劇的に軽くなる**
- 成長単位は**OSMのway（道路セグメント）**。ヘックスセルは使わない
  - GPS誤差5〜15mは最寄りの道へのスナップ（map matching）で吸収。誤塗りが起きない
  - フィクション（「この道が育つ」§4.3）と実装単位が一致する
  - 図鑑・シナリオ・安全ルールが全部OSM前提なので、データ基盤が一本化される
- 成長の入力は**1回の通過ごと**（初回踏破ではない）
  - 塗り（初回踏破）は本質的に広さへの報酬で、「通い続ける人が強い」と矛盾する
  - 核となる差別化は周辺機能（図鑑）ではなく**基本ループに載せる**

### 4.2 成長段階：無限だが線形ではない

> **無限にするのは「組み合わせ」であって「段階」ではない**

Lv.847の草を作らないための原則。

- 道単体：草 → 花 → 低木 → 木 → 生き物が住みつく
- **その先は分岐する**。歩き方で分岐先が変わる
  - 朝ばかり歩いた道 → 朝の性質
  - 雨の日に歩いた道 → 水の性質
  - 夜ばかり → 夜の性質
- 有限のパーツ × 分岐 = 組み合わせ爆発で無限に見せる

### 4.3 単位の繰り上がり

個別の道がカンストしても、**面としての完成度**が残る。

```
道 → 小径（3本繋がる） → 一帯（区画が揃う） → 地域
```

「あと1本でこの区画が繋がる」が、そのまま今日歩く理由になる。
無限に伸びるが、途中に**局所的な完成（マイルストーン）**を置いて達成感を作る。

### 4.4 図鑑

浄化ではなく**育成の成果**として生き物・植物が現れる。

- 中身は OSM の地物から自動で紐づく
  - 川沿い → カワセミ、トンボ / 坂の上 → 眺望 / 神社の木 → フクロウ / 公園 → 季節の花
- **有限**：基本図鑑（数ヶ月で埋まる。達成感の役）
- **無限**：季節4 × 時間帯3 × 天候3 = 36通りの変奏。同じ生き物でも「冬の朝」は別枠
- **同じ場所に通うほど近づく**（例：カワセミは同じ川に10回通って初めて現れる）
  → 行動範囲の狭さが有利になる中核メカニクス

#### 出現は決定的（確率を使わない）

- 条件を満たせば**必ず**出る。確率の外れは損失感＝**ガチャの再発明**で、§2に抵触する
- 残り回数は数字で見せず、**予兆**で匂わせる（川辺に青い羽根が落ちている、など）
  - 予兆＝期待を作る仕掛け。期限の使い方（§2「季節限定」）と同じ思想
  - 数字で見せると作業になり、完全に隠すと出現が唐突になる。予兆はその中間
  - **段は2つ（無し／もう近い）、出口は振り返りの中**（§11 決定事項ログ）。
    歩行中は振動1回だけで、「さっきの振動の中身」として帰宅後に予兆文が開く（§3の17:08）。
    歩行中に出すと予兆が予告に変わり、段を増やしても残り回数の言い換えになるだけ

#### 実在度：フィクション扱い、選定は実在の生態準拠

- その場所に実際にいるとは**主張しない**（「LLMに事実を書かせない」と整合）
- ただし**あり得ない生き物は出さない**（東京の川にカワセミはあり得る。ペンギンは出さない）
- 「戻ってくる」という世界観が、フィクションであることの免罪符として機能する
- 実際に見かけた生き物を記録する「実目撃」機能は将来枠（現実との接続の最強報酬候補）

### 4.5 振り返り（長期継続の本体）

- **散歩1回ぶんの振り返り**：帰宅後に開く1枚（§3の17:08）。所要1分で閉じられる密度にする
  - 構成は「今日の道（km）・時間・天候 → 今日育った道（低木→木）→ 図鑑（発見・予兆）→ 一言」
  - **数値は即時、文章は遅延**（architecture.md §5）。圏外でも数値サマリだけで成立し、
    パートナーの一言は生成でき次第差し込む（間に合わなければ定型文）
  - 中身は**確定データ（passage）から毎回再計算**する。歩行中の見込みは保存しない（§11）
- **月次スナップショット**：その月の地図を1枚の画像として永久保存
  - 何ヶ月も続けると、引っ越し・転職・旅行が地図のアルバムとして見える
- パートナーが語る形式にする（Wrapped 的な体験）
- **長文の出口はすべてここに集約する**（歩行中に出るのは1〜2文の断片のみ。§3・§6と同ルール）

## 5. パートナーAI

役割は**本物の記録の語り手**（§2の自己透明性に耐える唯一の話者）。
関係性の供給は、その結果として付いてくる。

### モデル：犬の散歩

責めない。ただ喜ぶ。それで飼い主は毎日歩く。
**罪悪感ゼロで最強の継続率**を出している現実の仕組みをそのまま実装する。

### 4つの仕事

1. **出発前に軽く誘う** — 「あっちの方、行ってみたいな」。指示ではなく願望。断ってもOK、催促しない
2. **歩行中に喜ぶ** — 発見・変化に反応。**1回の散歩で2〜3回だけ**（沈黙のデザインが命）
3. **帰宅後に語る** — 振り返りのナレーター。LLMの主戦場
4. **「今日どこ歩く？」に答える** — 天気・時間・履歴を踏まえた提案。**ゲーム抜きで実用的**なので、ゲームに飽きてもアプリが残る

### 記憶を持つ

> 「ここ、初めて来た日は何もなかったね」

事実は歩行ログのDBから渡し、LLMは文章化のみ担当。
→ ハルシネーションが構造的に起きない。

**記憶は単調化対策の本体でもある。**毎日同じ500m圏で反応するパートナーは、
対策なしでは数週間で同じことを言い始める（実際のコンテンツ枯渇はシナリオより先にここで起きる）：

- 発話履歴を場所ごとに記録し、**同じ切り口の再使用を禁止**する
- 時間が経つほど参照する記憶を深くする（昨日 → 1ヶ月前 → 季節前 → 初回）
- 蓄積した本物のログこそが、賞賛の透明性（§2）に耐える唯一の話材

### 入力方式：自由チャットは作らない

- 入力は「誘いに乗る／断る」「今日どこ歩く？」ボタン、選択肢式の返答まで
- 理由：自由チャットは沈黙のデザインを壊し、**雑談品質の維持という無限のスコープ**を開く
- パートナーは「語り手」であって「チャットボット」ではない（§2の位置づけと一致）

### スコープ防衛

- **姿を持たせない**（光の粒などの抽象表現）、または
- **その土地に戻ってきた生き物がそのままパートナー**になる（図鑑アセットを流用、追加コストほぼゼロ）
- 性格は歩いた場所で決まる（水辺ばかり歩く人には水辺寄りの相棒）

## 6. シナリオRPG（上物）

### 戦闘を作らない

| RPG要素 | 本作での実装 |
|---|---|
| 敵 | 到達すべき場所 + 必要な歩数。**強い敵 = 遠い / 長い** |
| 戦闘 | なし。そこまで歩けば解決 |
| レベリング | 街の育成をそのまま流用 |
| 謎解き | 到達で解錠される多段ヒントチェーン（詳細は後述） |

追加実装は **シナリオ生成・配置・進行管理のみ**。戦闘UI、アニメ、アセット不要。
「強い敵 = 長い距離」なので、数値インフレがそのまま運動量になる（Lv.847問題が起きない）。

### 3層構造

| 層 | 単位 | 期間 | 備考 |
|---|---|---|---|
| セッション | 散歩1回 | 30分 | |
| **一話** | 散歩1〜3回 | 数日 | 一話完結。逐次消化できる |
| **シナリオ群（章／アーク）** | 5話前後 | 2〜4週間 | ここで完結。バッドエンドもあり |

5話 ≒ 散歩10〜15回 ≒ 2〜4週間。
**「生活圏を一巡する期間」とほぼ一致する**（§9の規模感を参照）。
街を一周する頃に物語も完結する。

- **期限なし・失敗なし・中断自由**。3ヶ月放置しても続きから
- **敵は攻めてこない**。シナリオを受けていなければ何も起きない
- **モード選択はない**。散歩すれば土台は必ず育ち、シナリオは受けている時だけその上に乗る
  （「今日はどっちを進める？」という画面を作らない。選択疲れを作らない）

### 長期一貫性：骨格を先に一括生成する（最重要）

5話にまたがる伏線と整合性を、話ごとの逐次生成で保つのは不可能。
3話目で1話目の設定を忘れる。

**アーク開始時に、まとめて生成してDBに固定する：**

- 全5話の粗筋
- 登場人物・舞台となる場所（OSMから事前選定済みの候補を渡す）
- **結末候補を3つ**（グッド／ビター／バッド）

各話の詳細は、このプロットに沿って後から肉付けするだけ。
結末を先に決めておけば分岐も破綻しない。**逐次生成をやめるのが肝。**

### 中断対策：パートナーが「前回までのあらすじ」を語る

アークが長いぶん途中で放置される（放置に罰はない、は維持）。
問題は「戻ってきた時に話を忘れている」こと。
→ パートナーの役割として自然、かつLLMの得意分野。

### 街の状態が次のアークの生成材料になる

アークが終わっても街は残る。**次のアークを生成するとき、今の街の状態をプロンプトに入れる。**

- 「この一帯はもう森になっている」
- 「川沿いにカワセミが戻っている」

→ **自分が育てた街の現状が、次の物語の舞台設定になる。**
歩くほど次の物語の材料が増える。第1章と第5章では同じ場所が違う顔で登場する。
土台（街育成）と上物（シナリオ）が本当に接続する部分。

### 謎解き：シナリオを歩行量に変換する装置

謎解きの目的は知的密度ではなく**運動の誘発**。判定基準はただ一つ：

> **その仕掛けは、散歩を何回・何km生むか。**

テキストシナリオの弱点は「読めば終わる」＝消費速度が歩行量と無関係なこと。
謎解きは物語を物理的にN回の外出に分割し、
**シナリオの消費速度を歩行量に律速させる**。

- **シナリオの仕事**：行きたくさせる（動機の質）
- **謎解きの仕事**：1本の物語を何回もの散歩に引き延ばす（運動量への変換）

### 街は「問題」ではなく「器」

場所固有の謎（「◯◯が見える場所を探す」型）は**作らない。枯渇するから。**
街は有限かつ不変なので、解くほどプレイヤーの脳内に全域のインデックスが完成し、
残りの謎まで即答できるようになる。毎日遊ぶ自分用ゲームでは致命的。

- 謎はフィクション側（シナリオ内）で生成する。街はその**配達先**
- 盤面は同じでも棋譜は無限。地形が既知でも壊れない
- むしろ熟知しているほど候補が即座に浮かぶ＝**知悉が報酬になる**（「同じ場所に通う人が強い」と一致）

### 仕掛けの優先順位（運動量への寄与順）

| 仕掛け | 効果 | 備考 |
|---|---|---|
| **多段チェーン** | 到達しないと次のヒントが出ない。1話がN回の外出に分割される | 本命。地図アプリでズルしても歩数は減らない構造 |
| **条件到達** | 「朝にここ」「雨の日に」。同じ場所が2回分の外出になる | 純テキストでは作れない追加外出。期限ではなく条件なので原則に抵触しない |
| **熱い/冷たい** | 正解地点との距離で反応が変わる。直線往復が回遊になる | 距離計算のみで実装可。候補提示式（後述）では**候補間の絞り込み**として働く |
| 条件指定 | 座標でなく「水辺で、夜」と緩く指す。該当地点から自分で選ぶ | 運動ではなく自律性の供給。一意解を要求しない |
| 断片の統合推理 | 集めた断片から次の行き先を考える | 家の中の時間。次の出発動機として振り返りに軽く置く程度 |

家で解き切ってから回収に歩くのは**問題ない**（歩けば目的達成）。
最悪の失敗モードは「解けないから今日は行かない」＝運動が止まること。
**難易度の上限は「運動を止めない範囲」で決まる。**

**条件到達には代替解を必須にする。**「雨の日に」は乾季なら数週間止まり、
「解けないから行かない」と同型の「**条件が満たせないから行かない**」が起きる。
N日経過で時間帯条件などに自動緩和する。

### 謎の生成方式：答えを先に決めてからヒントを書く（逆向き生成）

LLMにヒントを書かせてから答えを探すと必ず破綻する（解の一意性を保証できない）。
順序を逆にする：

1. システムが正解地点とチェーン構造を先に確定（配置可能タグから選定。安全ルールをそのまま適用）
2. その地点の属性をLLMに渡し、**答えを知った状態で**ヒント文を書かせる
3. プレイヤーは地図上で行き先を選び、既存の到達判定で解錠

「章の骨格を先に一括生成して固定する」と同じ思想。
チェーン構造・条件の種類（型）は手書きで、文面のみLLM（§7と同じ分担）。
謎はフィクションに閉じるので実在の地物の性質を当てさせない
＝「LLMに事実を書かせない」にも抵触しない。一意性の機械検証も不要。

外れた場所に行っても「ここではなかった」＋フレーバーが返るだけ。
歩数は増え、街は育つ。損失ゼロ。
**だからヒントは論理的に厳密でなくてよい**（LLM生成の品質要求が一段下がる）。

### 謎をゲートにしない

- **候補は最初から見せる**（「地図上のこの5箇所のどれか」）
  - 自由回答は「LLMの気持ちを当てるゲーム」化する既知の不快パターンに入る
  - 当てずっぽうの不快が選択の楽しさに変わり、自律性の供給とも一致する
  - 外れ訪問でも歩数は稼げる構造はそのまま
- ヒントは段階制。最終的には**パートナーが答えを言う**
- 解けなくても必ず進める。自力で解いたかどうかは記録だけ残す
- 「ノーヒントで解いた」をエンディングと同じ棚に並べる＝**謎は関門ではなく収集物**

### 謎テキストの出口

- 到達時に出すのは**1〜2文の断片だけ**（沈黙のデザイン・歩きスマホ対策と整合）
- 断片の統合・パートナーの考察は**帰宅後の振り返りか、次の出発前**
- §4.5「長文の出口は振り返りに集約」をそのまま適用する
- **チェーンの解錠は1散歩1段が基本。次のヒントは帰宅後の振り返りで開く**
  - 路上で新しい目的地を提示しない＝「謎は出発前に提示する」（安全設計）と整合
  - 同じ散歩で複数段の地点を通っても、解錠は持ち帰り（翌日の楽しみになる）

### ジャンル指定（プレイヤーが選ぶ）

プレイ前にジャンルを指定 → その通りにシナリオが生成される。

- 実装コストはほぼゼロ（プロンプトに1語足すだけ）なのに体験が根本から変わる
- 「自分の物語を選ぶ」＝内発的動機の**自律性**を直接供給する
- 例：ほのぼの / ミステリー / ホラー / 冒険 / 日常

同じ画面で**緊張感（難易度）も選べる**ようにする。

| モード | 内容 |
|---|---|
| のんびり | 失敗なし。分岐だけ |
| ふつう | 分岐＋章の完結 |
| ハード | 期限あり、バッドエンドあり |

> **押し付けられた期限は義務。自分で選んだ期限は挑戦。**

同じルールでも選択権があるだけで負のフレームが消える。実装はフラグ1つ。
生活リズムに合わせて月ごとに変えられるのも大きい。

### 連続性と分岐

一話完結だが、**前回の結果が次回に影響する**。
「続きが気になる」＝損失ではなく期待による動機なので、原則に反しない。

**分岐の入力は「成否」ではなく「選択」。**

- 二又に来たらどちらを選ぶか。**どちらも正解**。物語の進む方向が変わるだけ
- 軸は「良い/悪い」ではなく **「明るい/暗い」**
  - ホラーを選んだ人にとって暗い展開は**報酬**。良し悪しではなく色

→ 歩けば必ず前進するのに、毎回違う物語になる。連続性と一回性が罰なしで両立する。

### エンディング＝コレクション

**「ゲームオーバー」ではなく「そのシナリオ群（章）の完結」。バッドエンドもエンドなので達成。**

一話単位のバッドエンドは軽いが、**数週間追いかけた物語の結末なら重みがある**。
名作の多くはビターエンドであり、コレクションとしての価値も高い。

- **章のリプレイはなし**。散歩が繰り返せないのと同じで、物語も一回きり
- エンディング棚は個別ではなく**系統**で埋める（グッド系／ビター系／バッド系 × 変奏）
  - どの章でも系統の空きを埋められる。**取り逃しが構造的に発生しない**
- バッドエンドは「次の章でわざと暗い選択をする」ことで収集する
  → 一回性が守られ、そのまま**次の章を始める動機**になる
- 「悪い結末」が損失ではなく**入手**になる

これにより、失敗判定を残しても罰にならない（別ルートに入っただけ）。

**リセットされるのはシナリオの進行状態のみ。
街の成長・図鑑・スナップショットは絶対に消さない。**

#### 文言ルール

| ❌ | ✅ |
|---|---|
| GAME OVER | 第3話 完 |
| 失敗しました | エンディング B に到達 |
| もう一度挑戦 | 次の話へ |
| 敵に負けた | 物語が別の方へ進んだ |

### 絶対のルール：時間経過では悪化させない

世界を動かすのは**プレイヤーの行動だけ**。

歩かなかった日は、物語の中でも何も起きていない。
3ヶ月ぶりに開いても、話は止まったまま待っている。
**「久々に開いたら大惨事」を一度でも起こしたら終わり。**

（＝「今日歩かないと悪いシナリオになる」は減衰の再発明。名前が違うだけで構造は同じ）

### 安全設計（必須）

**LLMに場所を選ばせない。** システム側が OSM タグで候補を絞り、
その中からLLMに割り当てさせる。

- 配置可能：公園、河川敷、神社、駅、公道、公共施設
- 配置禁止：民家、学校、病院、私有地、線路、危険箇所
- 自宅周辺のぼかし機能を最初から入れる

## 7. LLM運用方針

### 任せる

- 場所ごとのフレーバー（パートナーの一言として出す＝世界観を作り込まずに雰囲気が出る）
- 図鑑の記述文
- シナリオのフレーバーとパラメータ
- 月次振り返りの文章

### 任せない（手で決める骨）

- ルール・経済・成長の分岐ロジック
- 図鑑のカテゴリ体系
- 謎解きの型
- シナリオ配置場所の候補選定
- **実在の場所の事実**（歴史・由来は書かせない。書けるのは情景と感覚のみ）
  - ✅「登り切ると空が広い」 / ❌「この神社は江戸時代創建」

### コスト構造

- 1地点あたり約300トークン、Haiku級で十分
- **MVP（自宅周辺500m圏、数百地点）なら実質タダ**
- パートナーの一言は個人の歩行履歴（記憶）に依存するため、そもそも共有できない

将来マネタイズする場合のみ：場所の**基本**フレーバーは全ユーザーの共有資源にでき、
コストは地点数にしか比例しない（10万地点でも数十ドル規模）。
現状は完全ソロ前提なのでこの設計は持ち出さない。

### 生成タイミング：3段階（全パターン事前生成はしない）

分岐の全パターンを先に作るのは、組み合わせ爆発する上に
「今の街の状態を材料にする」が死ぬ（3話目の生成時点で街が変わっている）。
**実際に通る1本＋一歩先だけ**を生成する：

| 層 | タイミング | 内容 |
|---|---|---|
| アーク骨格 | 章の開始時に**一括・固定** | 粗筋・結末系統（長期一貫性の担保） |
| 話の肉付け | **直前生成**（前話の分岐確定後） | 振り返り〜次の出発前。今の街の状態を反映できる |
| 散歩中の断片 | **出発前にフロンティア先読み** | 次に到達しうる全地点ぶんの1〜2文。二又の物理選択にも両方用意済みで即応 |

- プレイ中（散歩中）のLLM呼び出しは**許可するが依存しない**
  - 外れ地点での即興フレーバー等の贅沢品として使う
  - 失敗・圏外なら定型文＋事前生成分で成立する（散歩は通信ゼロでも壊れない）
- 待たせてよいのは家の中だけ。**路上でLLMを待たせたら負け**

## 8. 世界観

**凝らない。** テキスト量とアート量でスコープが爆発し、確実に完成しなくなる。

必要なのは A4 半ページ：

- キーワード3語：**育てる / 戻ってくる / 一緒に歩く**
- トーン指定（静かで、説明しすぎない、2〜3文）
- 図鑑カテゴリ体系（公園 / 水辺 / 鉄道 / 農地 / 樹木 / 市街 / 夜 …。§9監査の4本柱に準拠）
- 出力JSONスキーマ

肉付けは全部LLMに回す。

### 地図の見た目

毎日見る画面だが、ここでも凝らない：

- **実地図の上に抽象レイヤー**（色の深まり＋わずかな揺らぎ程度）
- 具象イラスト（草・花・生き物の絵）は**図鑑の中だけ**
- 地図描画にアート量を投入しない。育ちの実感は**色と振り返り**で作る

## 9. 技術メモ

> 実装アーキテクチャ（KMP構成・MVVM・データモデル・フロー）は
> [architecture.md](architecture.md) に分離した。ここには概要設計に効く技術判断だけ残す。

- **プラットフォーム**：モバイルアプリのみ、**サーバー実装なし**（LLM APIは端末から直接呼ぶ）。
  Kotlin Multiplatform + Compose Multiplatform、地図ビューのみネイティブ埋め込み
- **オフラインファースト（ゲームロジック限定）**：記録・成長・判定は通信に**依存しない**
  （OSMデータは事前取り込み、断片は出発前に先読み）。プレイ中のLLM呼び出しは許可するが、失敗しても成立する（§7）
- **地図タイルはオンライン取得（OpenFreeMap、キー不要）**：常に最新のOSM背景が出る。
  タイルの生成・同梱作業が不要。圏外では背景が粗くなるだけ（キャッシュ済み範囲は表示される）で、散歩は壊れない
- **成長単位**：OSM way（道路セグメント）。map matching で最寄りの道にスナップ（§4.1）
- **GPS精度**：5〜15m、ビル街ではさらに荒れる。道へのスナップで吸収する
- **移動手段判定**：速度フィルタで「散歩の帰りに電車・バスに乗った」誤記録だけ防ぐ。
  開始が手動＋自分用アプリなので厳密な判定は不要（意図的チートは自己矛盾するだけ）
- **測位**：**セッション型に決定**（アプリ起動中のみ）。§3のコアループ
  （出発前→歩行中→帰宅後）が構造上すでにセッション型であり、
  バックグラウンド測位はこの区切りを壊す。バッテリー・実装の両面でも軽い。
  「散歩に出るぞ」という儀式になるのも在宅中心の生活に合う
- **地図データ**：OSM / 国土地理院。地物タグ（神社・階段・坂・橋・公園・踏切）が図鑑とシナリオの素材になる
- **状態管理**：減衰がないので `状態 = 歩行ログの累積`。再計算可能・オフライン耐性あり
- **天候は後付けで確定する**：セッションのタイムスタンプ＋位置から、帰宅後に天候APIで取得してログへ。
  分岐成長（雨の日の道）・条件到達（雨の日に来て）・図鑑変奏（天候3）の3機能がこれに依存する。
  散歩中の通信不要と両立し、「状態=ログの累積」の原則にもそのまま乗る
- **バックアップ（必須）**：「絶対に消さない」の単一障害点はスマホ本体。
  OS標準の自動バックアップにDBを乗せる＋手動エクスポート/インポートの2段構え（詳細は architecture.md）
- **APIキー**：LLM・天候等の外部APIキーは**設定画面からユーザーが入力（必須）**。
  初回セットアップで要求し、疎通確認が通るまでプレイを開始できない。
  端末のセキュアストレージに保存し、アプリにキーを埋め込まない
- **プロバイダは差し替え可能**：
  - 天候：Open-Meteo（キー不要）／OpenWeatherMap／Visual Crossing から選択
  - LLM：**AnthropicとOpenAIの2フォーマットのみ実装**。ベースURL・モデル名・キーは自由設定
    （OpenAI互換エンドポイントならOpenRouter・ローカルLLM等もそのまま使える）

### 規模感（MVP対象圏 500m ≒ 0.78km²、下記監査の実測）

- highway way は**376本・総延長38.9km**。うち歩行対象
  （residential / footway / unclassified / pedestrian / path）は**約220本・23km**
- 1日2km歩くと、**単純な踏破なら2週間弱で終わる**
- → だから「踏破」をゴールにしない設計（通過ごとの成長・分岐・季節変奏・シナリオ）が必須

### OSMデータ監査（2026-07-27実施、MVP対象圏）

図鑑・シナリオ・安全ルールが依存するOSMタグの充実度を、MVP対象圏
（都内の私鉄駅周辺500m。実名・実データは非公開のローカルメモに分離）で実測した。
**判定：500m圏で成立する。**

| カテゴリ | 500m圏の実データ | 示唆 |
|---|---|---|
| 水辺 | 中規模河川が圏内を通過（stream/river） | 水辺カテゴリ成立。カワセミ枠あり |
| 公園 | **15箇所**（児童遊園〜都立公園まで） | 最重要素材。配置候補も潤沢 |
| 鉄道 | 踏切6箇所、跨線歩道橋1 | 鉄道線が圏を南北に分断。踏切・歩道橋が「関門」のフレーバーになる |
| 農地 | farmland 5箇所 | 都市農地。季節変奏と相性がよい独自カテゴリ候補 |
| 公共 | 図書館、交番、小学校、保育園・幼稚園3 | 配置可能/禁止の判定材料が揃っている |
| 商店 | 個人店多数（米穀店、茶舗、菓子店…）＋チェーン | 市街カテゴリの素材 |
| 寺社 | 小祠2、教会1、神社1（ぎりぎり圏内） | **500m圏では手薄**（下記） |
| 街路樹 | natural=tree 25本 | 樹木カテゴリの点素材 |

わかった制約：

- 寺社・史跡は1km圏に厚い（神社3、寺院1、国史跡1、大規模公園1）
  → 行動圏拡張の報酬として自然に機能する。MVPの範囲は500mのままでよい
- ベンチ・水飲み場・トイレ等の微細アメニティはほぼタグ付けされていない（bench 1、toilets 1）
  → **図鑑素材を微細アメニティに依存させない**。公園・水辺・鉄道・農地の4本柱で組む
- 坂・階段のタグは steps 9本のみ。高低差の表現には地理院標高データの併用が必要

## 10. MVP スコープ

**まず自分の家の周り500m圏だけで成立させる。**

> **検証仮説（これ1行）：塗り＋図鑑＋帰宅後の一言だけで、2週目以降も自分は歩き続けるか。**

§9の実測では歩行対象の道は約23km＝**2週間弱で踏破が終わる**。
踏破後に歩く理由が残るかがこのMVPの合否。
再訪で育つ成長単位（通過ごとに段階が進む）をMVPに含めるのはそのため。
「踏破し尽くして飽きた」と「コンセプトが失敗した」を混同しないこと。

1. 歩行ログ取得 → 道へのスナップ → 通過ごとに段階アップ（減衰なし）
2. 図鑑（基本カテゴリのみ、季節変奏なし）
3. パートナー：帰宅後の一言のみ（出発前の誘いは後回し）
4. 月次スナップショット
5. LLM生成は事前バッチで数百地点だけ

**次フェーズ**：謎解き（多段チェーン＋条件到達）。シナリオRPGより先に入れる

- 実装は述語もソルバーも不要で、チェーン管理＋既存の到達判定のみ。シナリオ基盤より軽い
- 謎解きのチェーン構造はそのままシナリオのステップ構造になる。**別々に作らない**
- 実装順：**土台 → 謎解き → シナリオ**

**後回しでいいもの**：シナリオRPG本体、分岐成長、季節変奏、他プレイヤー要素

## 11. 決定事項ログ

| 論点 | 決定 | 理由 |
|---|---|---|
| 減衰 | **なし** | 負のフレームを排除。実装も軽くなる |
| 囲む or 塗る | **塗る** | 探索の楽しさを優先 |
| シーズンリセット | **なし** | ソロ完結なら積み上がる感覚が優先 |
| 上限 | **なし（分岐で無限）** | ただし線形インフレは禁止 |
| CPU対戦相手 | **なし** | 現実の街をAIに侵食されるのは不快。代わりにパートナー |
| パートナー | **あり** | LLMの受け皿。※位置づけは後に「本物の記録の語り手」へ更新（下記） |
| 戦闘 | **なし** | スコープ防衛。歩くことが行動 |
| 世界観 | **最小限** | 骨だけ手書き、肉付けはLLM |
| シナリオのジャンル | **プレイヤーが指定** | 自律性の供給。実装コストほぼゼロ |
| 難易度・緊張感 | **プレイヤーが選ぶ** | 自分で選んだ制約は罰にならない |
| シナリオの連続性 | **あり**（前回の結果が次回に影響） | 期待による動機。散歩に出る理由になる |
| 分岐の入力 | **選択**（成否ではない） | 「歩けなかった」を入力にしない |
| シナリオの粒度 | **3層**（散歩／一話／章5話前後） | 章の完結が振り返りの単位になる |
| シナリオ生成方式 | **章の骨格を先に一括生成して固定** | 逐次生成では長期一貫性が保てない |
| ゲームオーバー | **なし＝「章の完結」** | バッドエンドもエンド。表現の問題 |
| バッドエンド | **あり。コレクション化** | 損失ではなく入手にする |
| 時間経過での悪化 | **絶対になし** | 減衰の再発明を防ぐ |
| 謎解きの目的 | **運動の誘発**（基準＝散歩を何回・何km生むか） | 知的密度は手段。消費速度を歩行量に律速させる装置 |
| 謎の素材 | **フィクション側で生成**。場所固有の謎は作らない | 地形依存の謎は毎日プレイで枯渇する。街は器 |
| 謎の生成方式 | **逆向き生成**（答えを先に確定→ヒントを後書き） | LLMは解の一意性を保証できない |
| 謎のゲート化 | **なし**（段階ヒント→最後はパートナーが答える） | 「解けないから行かない」は運動停止＝最悪の失敗 |
| 謎解きの実装順 | **シナリオRPGより先** | 実装が軽く、チェーン構造がシナリオの土台を兼ねる |
| 測位方式 | **セッション型**（起動中のみ） | コアループが構造上セッション型。実装・バッテリーも軽い |
| 成長単位 | **OSM way（道）**。ヘックスセルは使わない | GPS誤差をスナップで吸収。フィクションと単位が一致 |
| 成長の入力 | **通過ごと**（初回踏破ではない） | 「通い続ける人が強い」を基本ループに載せる |
| パートナーの位置づけ | **本物の記録の語り手** | 自己透明性に耐えるのは本物のログだけ（§2） |
| 謎の提示 | **候補提示式**（この5箇所のどれか） | 自由回答は「LLMの気持ちを当てるゲーム」化する |
| 条件到達の代替解 | **必須**（N日で自動緩和） | 「条件が満たせないから行かない」を防ぐ |
| セッションの区切り | **開始は手動、終了は自動検知** | 儀式性と押し忘れ対策の両立 |
| 開始押し忘れの日 | 歩数だけ拾って言及（成長なし・損失扱いもなし） | 「歩いたのに損した」を作らない |
| 歩行中のフィードバック | **振動1回のみ**。中身は帰宅後 | 沈黙のデザイン。「何だろう」を持ち帰らせる |
| 図鑑の出現 | **決定的**（確率なし）。予兆で匂わせる | 確率の外れは損失感＝ガチャの再発明 |
| 図鑑の実在度 | フィクション扱い、選定は実在の生態準拠 | 事実を主張せず、あり得ない生き物も出さない |
| パートナーへの入力 | **自由チャットなし**（選択肢＋ボタンのみ） | 沈黙のデザイン防衛。雑談品質は無限のスコープ |
| 章のリプレイ | **なし**。エンディング棚は系統別 | 一回性を守る。バッドは次章の選択で収集 |
| シナリオと土台 | **常に同時進行**（モード選択なし） | 散歩すれば必ず育つ。選択疲れを作らない |
| 地図の見た目 | **実地図＋抽象レイヤー**。具象は図鑑のみ | アート量のスコープ防衛 |
| 標準歩行距離 | **1日30分 ≒ 2km** | 一般的な散歩1回分。全チューニングの基準単位 |
| チェーンの段数 | **1話 = 2〜3段** | 「一話＝散歩1〜3回」（§6の3層構造）とそのまま一致 |
| 歩行中の画面 | **ONのまま携行が基本**（画面オフ耐性は保険扱い） | 測位が単純になる。UIは最小で操作を要求しない |
| 歩行中の操作 | **到達点のみ**。立ち止まって断片を読む＋最大1タップ | 移動中は要求ゼロ。重い作業は帰宅後に持ち帰る |
| プラットフォーム | **KMP + Compose Multiplatform**（地図のみネイティブ） | コード制約が少なく共有最大。画面数が少なくCMP向き |
| サーバー | **なし。端末完結**（LLM APIは直接呼ぶ） | 個人利用前提。配布時のみプロキシが必要（唯一の破れ目） |
| アーキテクチャ | **MVVM + UseCase、単方向データフロー** | 「状態=ログの累積」を実装原則に昇格。詳細は architecture.md |
| オフライン | **ゲームロジックは通信不要**。地図タイルはオンライン | 圏外は背景が粗くなるだけ。記録・成長は壊れない |
| 地図タイル | **OpenFreeMap**（MapLibre＋オンライン、キー不要） | 常に最新のOSM。タイル生成・同梱の作業が不要 |
| シナリオ生成のタイミング | **3段階**（骨格一括→話は直前→断片は先読み） | 全パターン事前生成は組み合わせ爆発＋街の状態が古くなる |
| プレイ中のLLM呼び出し | **許可するが依存しない**（失敗時は事前生成分で成立） | 路上でLLMを待たせない |
| チェーンの解錠粒度 | **1散歩1段**。次のヒントは帰宅後に開く | 路上で新しい目的地を提示しない（安全設計と整合） |
| 天候データ | **後付け確定**（タイムスタンプ＋位置で帰宅後にAPI取得） | 散歩中オフラインと天候依存3機能を両立 |
| バックアップ | **OS自動バックアップ＋手動エクスポート**の2段構え | 「絶対に消さない」の単一障害点（端末）を潰す |
| APIキー管理 | **設定画面でユーザーが入力（必須）**、セキュアストレージ保存 | 初回セットアップで疎通確認まで要求 |
| 天候プロバイダ | **複数対応・選択制**（Open-Meteo／OpenWeatherMap／Visual Crossing） | Open-Meteoはキー不要。抽象IF越しに差し替え |
| LLMプロバイダ | **Anthropic／OpenAIの2フォーマットのみ実装**。接続先・モデルは自由設定 | OpenAI互換ならローカルLLM・中継サービスも使える |
| 移動手段判定 | **速度フィルタのみ**（厳密判定はしない） | 開始手動＋自分用。誤記録防止だけで足りる |
| 予兆の具体表現 | **2段（無し／もう近い）**。出口は**振り返りの中の予兆文**（歩行中は振動のみ） | 歩行中に出すと予兆が予告になる。段を増やしても残り回数の言い換えになるだけ |
| 振り返りの組み立て | **確定データから毎回再計算**（歩行中イベントは永続化しない） | 見込みを保存すると確定値と食い違う表が残る。過去の散歩でも同じ振り返りが出る（冪等） |
| 振り返りの一言 | **帰宅直後に1件だけ生成**。従量回線でも投げる | 事前に作れない唯一の生成物で、遅れると定型文のまま閉じられる |
| 一言の切り口 | **場所ごとに1つだけ指示**（`utterance_log` で使用済みを避ける） | 禁止リストを渡すと出力が不安定になり、履歴が伸びてプロンプト指紋も動く |
| 切り口の枯渇 | **いちばん古く使った切り口を再利用**（無言にしない） | 毎日歩いている人にだけ沈黙が返るのは §5「責めない。ただ喜ぶ」に反する |
| 一言の材料の基準時刻 | **そのセッションの `started_at`**（現在時刻は使わない） | 時間で変わる事実を入れると指紋が動き、毎回定型文＋再生成（＝課金）になる |
| 記憶の深さ | 初回 ＞ 季節前 ＞ ひと月前 ＞ 最近。浅い記憶しか無ければそれを使う | §5「時間が経つほど深くする」。深い記憶が無いことを無言の理由にしない |
| ブランクへの言及 | **なし**。「何日空いたか」を材料として持たない | 禁止文だけでは滲む。負のフレーム（§2）はデータの形で排除する |
| 押し忘れの言及 | 直近2日・記録が無い日だけ。歩数は3段階に丸めて渡す | 「歩いたのに損した」を作らない一方で、記録の指摘にも数字の羅列にもしない |
| 発話履歴の位置づけ | **真実の源に準ずる追記ログ**（`passage` から再計算できない） | 消すと単調化対策そのものが失われる。バックアップ対象（architecture.md §6） |

## 12. 保留・要検討

- エンディングの系統数と変奏の深さ（LLM生成でどこまで担保するか）
- 帰宅の自動検知の精度（自宅ジオフェンス＋停止判定で十分か。誤検知時は手動終了ボタンで上書き）
- ジャンルの選択肢をいくつ用意するか
- 他プレイヤーの存在をどこまで見せるか（現状は完全ソロ想定）
- マネタイズするのか、自分用に留めるのか
- パートナーの姿（抽象表現 or 生き物流用）

## 13. リスク

| リスク | 対策 |
|---|---|
| 端末紛失・故障でデータ全喪失 | OS自動バックアップ＋手動エクスポートの2段構え。導出は再計算で復元 |
| スコープ爆発 | 戦闘・アート・長編ストーリーを作らない。MVPを500m圏に限定 |
| 現実の場所への物語配置 | LLMに場所を選ばせない。OSMタグで公共空間のみに限定 |
| 位置情報の露出 | 自宅周辺ぼかしを初期実装 |
| 歩きスマホ・私有地侵入 | 歩行中はUIを最小化。危険箇所を配置候補から除外 |
| 謎を「探して」私有地に近づく | 謎の答えにも配置ルールを適用。謎は出発前に提示し、現地は到達通知のみ |
| 夜間条件の謎で住宅街を徘徊 | 夜の謎は幹線道路沿い・駅前に限定（**夜の公園も除外**） |
| LLMの事実誤り | 事実はDBから渡す。情景と感覚のみ生成させる |
| パートナーの発話の単調化 | 発話履歴の再使用禁止＋記憶参照を時間とともに深くする（§5）。実際の枯渇はシナリオより先にここで起きる |
| コンテンツ枯渇 | 分岐 × 季節 × 時間帯 × 天候 の組み合わせ、およびシナリオ無限生成 |
