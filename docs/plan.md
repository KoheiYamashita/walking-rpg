# 実装プラン

概要設計は [design.md](design.md)、実装設計は [architecture.md](architecture.md)。
タスクの実体はGitHub issue（ラベル `M0:基盤`〜`M7:iOS`・`運用`）。ここは全体像だけ。

最終更新: 2026-07-30

## 方針

- **両OS同時開発（KMP + CMP）、動作検証はAndroid実機優先**。iOSはM7でまとめて追いつく
- 実装順は決定事項どおり：**土台 → 謎解き → シナリオ**。M0〜M2（土台）は完了済み
- **M3（実地検証）と M4以降の実装は並行して進める**（2026-07-30 方針更新。
  当初は「M3の結果を見てから切る」だったが、設計済み項目を全部入れる方針に変更）。
  ただし検証仮説の判定を汚さないよう、**検証期間中の検証端末はM2ビルドのまま**を推奨
  （謎解きが入った端末では「塗り＋図鑑＋一言だけで続くか」を判定できない）
- 天候は**プロバイダ選択制**（Open-Meteo／OpenWeatherMap／Visual Crossing。既定はキー不要のOpen-Meteo）
- LLMは**Anthropic／OpenAIの2フォーマットのみ実装**し、ベースURL・モデル名・キーは自由設定
  （OpenAI互換エンドポイント対応）。初回セットアップで疎通確認まで必須

## 依存の要点（クリティカルパス）

```
M2完了 ─┬─ #44 チェーン基盤 ─┬─ #45 配置候補 ─── #47 ヒント生成 ─┐
        │                    ├─ #46 チェーン進行 ── #49 条件到達  ├─ #50 アーク骨格 ── #51 肉付け ─┬─ #52 棚
        │                    └─ #48 謎UI ────────────────────────┘                                └─ #53 あらすじ
        ├─ #54 誘い / #55 どこ歩く？ / #56 Wrapped / #57 変奏 / #58 分岐成長（並行可・依存なし）
        └─ #62 Health Connect（並行可）

#19 実地検証（M2ビルドで並行） ── 結果 → M4〜M6の優先順位を再調整

#2（済）── #3 iOS測位スパイク ── #60 iOS実装一式 ── #61 iOS実機検証
                                  #4 iOS地図SPM ──┘
```

- **M4はM5の前提**（チェーン構造がそのままシナリオのステップ構造になる。別々に作らない）
- **M6の6件は相互に独立**で、M4/M5とも独立。すき間に並行で入れられる。
  推奨順は #56 Wrapped → #54 誘い → #55 どこ歩く？ → #57 変奏 → #58 分岐成長 → #59 実目撃
  （M2の基盤の延長で軽い順・体験に効く順）
- **#58 分岐成長は #50 アーク骨格と接続すると効果的**（「街の状態が次の物語の材料になる」）ので、
  M5着手前に済ませておくと良い
- **M7はM4〜M6と独立**。#3（測位スパイク）が唯一の技術リスクで、それ以外は差し替えのみ
- #63（25MB対策）はデータが貯まり始めるM3以降でよい。#64はデータ移行・圏拡張のタイミングまでに

## スコープ外（このプランでもやらない）

- 他プレイヤー要素（完全ソロ想定のまま。design.md §12の保留）
- マネタイズ・配布（サーバーなし・APIキー直入力の個人利用前提。配布時はプロキシが必要＝唯一の破れ目）
- 自由チャット（決定事項。§11）
- 戦闘・アニメ・具象アートの作り込み（スコープ防衛の原則）
